## High Priority Findings

### 1. Fingerprint API Is Open

Files:

- `routes/api.php`
- `app/Http/Controllers/Api/FingerprintApiController.php`

Routes:

```php
Route::post('/attendance/push', [FingerprintApiController::class, 'push']);
Route::post('/iclock/cdata', [FingerprintApiController::class, 'push']);
```

Problem:

- No auth middleware, token, signature, or strict machine validation.
- Unknown machine rejection is commented out.

Recommended fix:

- Add a shared secret/token or machine API key.
- Validate known machine serial number/IP.
- Return `401` for unknown or invalid requests.
- Add tests for valid and invalid fingerprint push.

### 2. Role Enum Compared To String

File:

- `app/Http/Controllers/JadwalController.php`

Problem:

```php
if ($user->role === 'guru') {
```

`User::role` is cast to `App\Enums\UserRole`, so this comparison is likely wrong.

Recommended fix:

```php
use App\Enums\UserRole;

if ($user->role === UserRole::Guru) {
```

or:

```php
if ($user->role?->value === 'guru') {
```

### 3. Duplicate And Over-Broad Resource Routes

File:

- `routes/web.php`

Examples:

- `Route::resource('tahun', TahunController::class);`
- `Route::resource('kelas', KelasController::class);`
- `Route::resource('pegawai', PegawaiController::class);`
- `Route::resource('kelassiswa', KelasSiswaController::class);`

Problem:

- Some resources are registered once under `auth,active`, then again under `role:admin,operator`.
- This can expose master data routes more broadly than intended.

Recommended fix:

- Keep public authenticated dashboard/report routes separate.
- Put create/update/delete/import/export master data routes only inside `role:admin,operator`.
- Use `only()` / `except()` on resource routes.

### 4. Resource Routes Point To Missing Controller Methods

Files:

- `routes/web.php`
- `app/Http/Controllers/FingerprintMachineController.php`
- `app/Http/Controllers/SpecialEventController.php`
- `app/Http/Controllers/ScheduleOverrideController.php`

Problem:

- `Route::resource()` creates full CRUD routes.
- Some controllers do not implement all methods such as `show`, `edit`, or `update`.

Recommended fix:

- Use `only([...])` or `except([...])` for incomplete resources.
- Or implement the missing methods if the UI needs them.

### 5. `$request->all()` After Partial Validation

Files:

- `app/Http/Controllers/PegawaiController.php`
- `app/Http/Controllers/SiswaController.php`
- `app/Http/Controllers/SekolahController.php`

Problem:

- Some store/update methods validate only a few fields, then save `$request->all()`.
- This can allow unexpected fillable fields to be saved.

Recommended fix:

- Save only validated data.
- Use Form Request classes for large forms.

## Medium Priority Findings

### 1. Two Factor Authentication Is Present But Not Fully Active

Files:

- `config/fortify.php`
- `app/Http/Middleware/RequireTwoFactor.php`
- `app/Http/Controllers/TwoFactorController.php`
- `app/Http/Controllers/TwoFactorChallengeController.php`
- `resources/views/login/2fa-setup.blade.php`
- `resources/views/login/2fa-challenge.blade.php`

Problems:

- Fortify 2FA feature is commented.
- `2fa.*` routes are not registered in `routes/web.php`.
- `2fa` middleware is not applied to protected route groups.
- Some code compares enum role to strings.

Recommendation:

- Decide whether to use Fortify-native 2FA or this custom 2FA flow.
- Do not keep both half-configured.

### 2. Eloquent Many-To-Many Relation Keys Look Wrong

Files:

- `app/Models/Siswa.php`
- `app/Models/Kelas.php`
- `app/Models/Tahun.php`
- `database/migrations/2024_05_12_055121_create_kelas_siswas_table.php`

Pivot table columns:

- `siswa_id`
- `kelas_id`
- `tahun_id`

Problem:

- Several `belongsToMany()` definitions appear to use wrong foreign/related pivot keys.

Recommendation:

- Revisit these relationships carefully.
- Add tests proving `Siswa -> kelas`, `Siswa -> tahun`, `Kelas -> siswa`, and `Tahun -> siswa/kelas`.

### 3. Debug Statements And Temporary Files

Recommendation:

- Remove or move debug scripts outside production repo.

### Current Priority Findings

1. **Authorization and route organization**
   - `routes/web.php` registers several resources in the broad `auth,active` group before the restricted role group.
   - Current write routes without `RoleMiddleware` include attendance mandatory/override actions, dashboard resource mutations, and `kelassiswa/bulk-delete`.
   - Several resource registrations expose actions that their controllers do not implement, including override `show/edit/update` routes.
   - Fingerprint push API routes remain unauthenticated and accept unknown machines.

2. **Incorrect Eloquent pivot relationships**
   - `Siswa::kelas()`, `Siswa::tahun()`, `Kelas::siswa()`, `Kelas::tahun()`, `Tahun::kelas()`, and `Tahun::siswa()` use swapped pivot foreign/related keys.
   - The source of truth is `kelas_siswas(siswa_id, kelas_id, tahun_id)`.

3. **Unsafe or inconsistent input handling**
   - `SiswaController`, `PegawaiController`, and `SekolahController` still build persisted data from `$request->all()` after only partial validation.
   - Large forms should move toward Form Requests and save validated data only.

4. **Enum and 2FA inconsistencies**
   - `User::role` is cast to `UserRole`, but several controllers and middleware compare it to raw strings.
   - Custom 2FA code remains incomplete/inconsistent with Fortify and is not currently a finished protected flow.

5. **Test isolation and test value**
   - Several feature tests deliberately avoid `RefreshDatabase`, reuse development records, mutate existing users or active years, and manually clean up.
   - `FingerprintRefactorTest` repeats controller logic instead of exercising the HTTP endpoint, so it cannot catch endpoint regressions.

6. **Maintainability and cleanup**
   - Active `dd()` remains in `app/Livewire/Mapel/Data.php`.
   - Large controllers include `JadwalController` (~529 lines) and `AbsensiController` (~495 lines).
   - The repository contains duplicate, backup, debug, scratch, and temporary files; do not delete them without explicit user approval.
